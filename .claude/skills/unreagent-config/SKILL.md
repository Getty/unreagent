# unreagent — configuration

One config file lives next to the `.uproject` and is **committed by the user**;
a git-ignored `unreagent.local.yaml` overlays it with machine specifics. The
committed file must stay portable — that portability is the reason the
placeholder system exists.

## Load order (`config.Load`)

1. Resolve the path: `-config <path>`, else `unreagent.yaml` next to the
   executable (`findConfig`).
2. Decode `unreagent.yaml`.
3. If `unreagent.local.yaml` exists, decode it **into the same struct**. This is
   a YAML-decode overlay, not a deep merge: a scalar wins, an absent key leaves
   the base value alone, and a provided list or map **replaces** the base one
   wholesale. Users expecting to append one item to `agent.args` will instead
   replace the list — remember this when documenting a new list-valued field.
4. `applyDefaults()` — fills empty values. Note that the zero value is
   indistinguishable from "not set" for plain `bool` and `int`; fields whose
   default is `true` are therefore `*bool` (`Unattended`, `KillCrashReporter`,
   `PowershellTool`, `Window`) and read through `boolVal()`. Use `*bool` for any
   new option that defaults to on.
5. Resolve engine and project, write the resolved project path back into the
   config, then `substitute(...)`.
6. `validate()` — reject bad enum values here, not at the point of use.

## Placeholders

| Placeholder | Resolution |
|---|---|
| `${ENGINE}` | env `UE_ROOT` → `engineRoot` (usually local.yaml) → autodetect (registry, Epic default paths) |
| `${PROJECT}` | full path to the `.uproject` (autodetected next to the config) |
| `${PROJECT_DIR}` | its directory |
| `${PROJECT_NAME}` | its filename without extension |

`substitute` runs a `strings.Replacer` over **all string values** in the config,
including nested maps (`substituteAny` walks `mcp.extraServers`). So a new
string field gets placeholder support for free — and a field that must *not* be
substituted needs deliberate handling. Order matters in the replacer:
`${PROJECT_DIR}` and `${PROJECT_NAME}` are listed before `${PROJECT}` so the
longer keys win.

## Adding a field — the full checklist

A config option is not done when the struct compiles. All of these move
together:

1. **Struct field + `yaml:` tag** in `internal/config/config.go`, in the section
   it belongs to (`unreal`, `agent`, `mcp`, `permissions`, `runtimes`,
   `files`, `commands`).
2. **Default** in `applyDefaults()` — `*bool` if it defaults to true.
3. **Validation** in `validate()` if it is an enum or a path that must exist.
4. **Use site** — usually `cmd/launcher/main.go`.
5. **`unreagent.example.yaml`** — commented, with the default stated.
6. **`README.md`** — the quick-reference table under "Configuration", plus prose
   if the option changes observable behavior.
7. **Test** in the style of the existing ones: defaults applied, override
   honoured, invalid value rejected.

Skipping 5 and 6 is the usual failure — an option nobody can discover is an
option that does not exist.

## Things that are auto-derived, deliberately

`unreal.editor`, the built-in `compile` and `package` commands, `files.root` and
the project path all have placeholder-based defaults so that a minimal config is
genuinely minimal (see README "Setup"). Preserve that property: a new option
should have a default that works, not one that forces an entry in every user's
config.

## Secrets

`mcp.token` is generated by `hermes-setup` and written to
`unreagent.local.yaml` (git-ignored) via `persistGeneratedToken`, never to the
committed file. Any future secret follows the same path. `writeYAMLAtomic`
(temp + rename) is the house pattern for writing user config — a crash
mid-write must not leave a half-file.
